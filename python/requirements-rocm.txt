# SimpleMindsAI — Python compute plane, AMD ROCm backend.
#
# For the Ryzen AI HX 370 / Radeon 890M (gfx1150) deployment host. Installs the
# vendor-neutral dependencies, then the ROCm build of torch:
#
#   pip install -r requirements-rocm.txt
#
# ARCH CORRECTED 2026-10-10: the HX 370 / 890M is gfx1150 (RDNA 3.5, Strix
# Point), confirmed by `rocminfo` on the deployment host and by AMD's ROCm 7.14
# PyTorch support matrix. The earlier gfx1151 pin was wrong — gfx1151 is Strix
# Halo (Ryzen AI Max / Radeon 8050S), a different APU, and would have pulled the
# wrong device package.
#
# The multi-arch wheels are self-contained: a host `torch` wheel plus the
# device-specific `rocm-sdk-device-gfx1150` and ROCm libraries, all from
# repo.amd.com. PyTorch therefore does NOT depend on the distro-packaged ROCm;
# only the in-kernel amdgpu driver and the gfx target matter. The `+rocm7.14.0`
# tag names the AMD ROCm release the wheel carries, not `apt`'s ROCm version.
#
# After install, confirm the backend and that the GPU is really targeted:
#
#   python -c "import torch; print(torch.version.hip, torch.cuda.get_device_properties(0).gcnArchName)"
#   python -m sma.brain preflight        # full platform + bf16 + parity report
#
# Notes for this backend:
#   - The torch device type is still "cuda" under ROCm (the namespace is kept
#     for compatibility); the vendor is recorded as backend="rocm" in
#     provenance, which is why that field exists separately from `device`.
#   - 8-bit Adam (bitsandbytes) is NVIDIA-only and has no ROCm equivalent. The
#     3B memory preflight must use Adafactor here instead.
#   - This is an APU: the device reports a shared memory carve-out as its
#     `total_memory`, not a dedicated VRAM budget. Do not size a 3B run against
#     it as if it were a discrete card.

-r requirements.txt
